# 付録A 申請の総合チェックリスト

印刷して、手元に置いてください。上から順に、チェックしていきます。

```
【契約と登録】
□ Apple Developer Program に加入
□ 有料App契約を承認（Account Holder）／口座・税務を入力（自分で）
□ Bundle ID を登録（変更不可）
□ App Store Connect で新規アプリを作成
□ （課金）非消耗型の商品を作成。製品IDを控える（変更不可）
□ （広告）AdMobでアプリと広告ユニットを作成。同意メッセージを公開

【公開ページ】
□ サポートページ（https の公開URL、連絡先つき）
□ プライバシーポリシー（https の公開URL）
□ 公開してよい氏名・メールだけを載せた

【アプリ側】
□ 本番の値は gitの外（Secrets）。ソースにIDを書いていない
□ リリースガード（空・テストID・見本の値・形式不正・テストモード）が効いている
□ プライバシーマニフェスト：理由の申告が必要なAPIを宣言。
  NSPrivacyTracking とドメインが矛盾しない。空のドメイン配列がない
□ 権限の説明文（NS…UsageDescription）。ATTの説明文
□ 暗号化の申告（ITSAppUsesNonExemptEncryption）の内容が正しい
□ 素材（フォントなど）のライセンス全文を、アプリの中に載せた
□ アイコン 1024×1024、透過なし
□ ビルド番号が、前回より大きい

【ビルド】
□ 実行先 Any iOS Device (arm64) → Product → Archive
□ Distribute App → App Store Connect → Upload → 「Upload Successful」
□ 数時間、自動検証のメール（ITMS-）を待つ
□ 処理済みのビルドを、バージョン画面で選んで、保存

【App Store Connect】
□ スクリーンショット：必要なサイズの欄を、すべて埋めた（6.9インチ、6.3インチ）
□ 名前・サブタイトル・説明・キーワード・最新情報（上限内）
□ サポートURL（日本語、必須）・プライバシーポリシーURL
□ アプリのプライバシー：回答して「公開」
□ コンテンツ配信権：アプリの中身に合わせて回答
□ 年齢制限・カテゴリ・著作権
□ （課金）商品の情報と審査用スクリーンショット
□ 審査メモ・連絡先（電話は +81 の形）
□ 価格・配信国・リリース方法

【提出】
□ 「審査用に追加」で、エラーの一覧が出ない
□ 提出 → 「審査待ち」を確認
□ メールを確認（ITMS-、App Review）

【実機の確認（できるだけ）】
□ 音・声・機内モード・着信・実際の広告・同意とATT・課金と復元
```

# 付録D 実装が完了したら、Claude Codeに貼る依頼文

次の文章を、**そのまま**、Claude Codeに貼ってください。`{{…}}` の部分は、あなたのアプリの値に置き換えます（分からない部分は、そのまま残しても構いません。AIが、質問します）。

```
あなたは、iOSアプリ「{{アプリ名}}」の公開準備を担当するエンジニアです。
実装は完了しています。App Store Connectに提出するために必要なものを、
このリポジトリの実際の状態から調べて、一式、用意してください。

# 守ること（最優先）
1. 実行していないことを、実行したと書かない。実行できなかった検査は NOT RUN と書く。
   実機でしか確認できないこと（音・声・実際の広告・本番の課金・機内モード）を、
   シミュレータの結果で「確認済み」にしない。失敗は失敗と書く。テストを緩めて通さない。
2. 本番のID、鍵、パスワード、口座、税務の情報を、コードにも、gitにも、
   出力にも書かない。私が渡していない値を、作り話で埋めない（プレースホルダーにする）。
3. 次の操作は、私の了承を得てから行う：
   外部サービスへの公開（GitHub Pagesなど）、リポジトリの公開、push、アップロード、提出。
   氏名やメールアドレスが公開されるときは、公開される内容を明示して確認する。
4. App Store Connect、AdMob、GitHubなどの画面の操作は、私がやる。
   あなたは、入力する文字、画像、手順、URLを、コピーできる形で用意する。
5. 私に質問してよいのは、私しか知らないこと（提供者名、連絡先メール、価格、
   既存の公開サイトのURL、Bundle IDの最終決定）だけ。それ以外は、既定値を決めて進める。
6. 規約や画面の名前は変わる。確信のないことは「報告に基づく」「要確認」と書く。
   可能なら、公式ドキュメントを調べ、出典のURLを付ける。

# 私の基本情報（分かるものだけ）
- アプリ名：{{アプリ名}}　　　Bundle ID：{{Bundle ID}}
- 提供者名（公開される）：{{氏名または屋号}}　　連絡先メール（公開される）：{{メール}}
- 価格：{{無料／有料／アプリ内課金あり}}　　配信国：{{日本のみ／…}}
- 既存の公開サイト：{{URL／なし}}
- 広告：{{AdMobを使う／使わない}}　　課金：{{非消耗型あり／なし}}

# 手順

## 0. 調査（出力：APP_FACTS.md）
リポジトリを読み、次を事実として一覧にする（推測は「推測」と明記）。
- Bundle ID、バージョン、ビルド番号、最小iOS、対応デバイス（iPhone専用か）、向き
- 使っているSDK（SwiftPM/CocoaPods）と、そのバージョン
- Info.plistの権限の説明文、ATT、暗号化の申告、UIAppFonts
- プライバシーマニフェスト（アプリ本体と、SDKのもの）の中身
- 広告・課金・解析・ネットワーク通信の有無。ユーザーの入力を外部に送っていないこと
- 同梱している素材（フォント、画像、音、動画）と、そのライセンス
- 保存するデータの場所と種類

## 1. 事前の点検（出力：PREFLIGHT.md）
次を実行し、結果をそのまま記録する。
- Releaseビルドが、空・テスト用ID・見本の値・形式不正・広告テストモードで失敗する仕組み
  （リリースガード）があるか。なければ作り、そのテストも書く。
- プライバシーマニフェストの整合：NSPrivacyTracking が true ならドメインが1つ以上、
  ドメインがあるなら true、空のドメイン配列は不可（ITMS-91064）。ビルド時に検査する。
- 理由の申告が必要なAPI（UserDefaults、ファイルの日時、起動時間、ディスク容量など）の
  使用と、マニフェストの宣言の一致（実行ファイルのシンボルも調べる）。
- Info.plistに、使う機能の説明文があるか。
- アイコンが 1024×1024、透過なしか。
- ビルド番号が、App Store Connectにすでにアップロードした番号より大きいか（私に確認）。
- 秘密の値が、git管理下に入っていないか。
- 未コミット、未pushの変更の有無。
- 無害な警告（例：サードパーティSDKのdSYM欠落）と、本当の問題を分けて書く。

## 2. 公開ページ（出力：site/index.html, site/privacy-policy.html）
- サポートページ（よくある質問＋連絡先）と、プライバシーポリシーを、日本語で作る。
- 内容は、APP_FACTS.md の事実だけに基づく（収集するもの／しないもの、広告SDKが収集し得る
  もの、ATT、課金はAppleが処理、問い合わせ先、制定日、提供者名）。
- 公開は、私の了承を得てから。GitHub Pagesで公開する手順を示す（サイト専用の別リポジトリ）。

## 3. ストアの文言（出力：store/APP_STORE_COPY.md と、コピーボタンつきの store/submission-kit.html）
上限を守って、日本語で書く。文字数も表示する。
- サブタイトル30／プロモーション170／説明4000／キーワード100（半角カンマ）／最新情報
- 課金：参照名、製品ID案、表示名30、説明45、審査メモ
- 審査メモ、サインインの要否、連絡先の書式（電話は +81 の形）
- 年齢制限の回答、カテゴリ案、著作権、価格と配信の案
- コンテンツ配信権の回答（素材のライセンスを監査して、根拠つきで）
- 輸出コンプライアンスの回答案（私の申告になる点を明記）
- 実際にない機能、根拠のない最上級の表現、他社名を、書かない。期待とのずれは、説明に書く。

## 4. プライバシーの回答（出力：store/PRIVACY_ANSWERS.md）
- 「Appのプライバシー」のデータ収集の回答を、APP_FACTS.md と、SDKの公式の開示ページに基づいて、
  項目ごと（収集する／しない、用途、ユーザーへの紐づけ、トラッキング）に作る。
- 公式の根拠がない区分は、保守的に答え、「要確認」と書く。出典URLを付ける。
- 回答は、保存したあと「公開」まで押すことを、手順に書く。

## 5. 画像（出力：store/UPLOAD/）
- UIテスト（XCUITest）で、撮影用のデータを使い、画面を自動で撮る。環境変数で出力先を渡す。
- シミュレータのステータスバーを 9:41・電池100% にする。
- 必要なサイズの欄ごと（少なくとも 6.9インチ 1320×2868 と 6.3インチ 1206×2622）に撮る。
  App Store Connectが求める他のサイズがあれば、私に聞く。
- 見出し付きの宣伝用と、画面そのままの2種類を作る。見出しは、実在する機能の価値だけ。
- 課金がある場合は、審査用のスクリーンショット（購入ボタンが写る画面）も作る。
- アプリプレビュー動画は、画面の録画であること。静止画のスライドショーは、
  「審査で指摘される恐れがある」と明記し、提出に使うか、私に確認する。
- store/UPLOAD/README_UPLOAD.md に、どのフォルダを、どの欄に入れるかを書く。

## 6. 検証（出力：docs/VERIFICATION.md）
実際に実行して、コマンドと結果を、そのまま記録する。
- 単体テスト、UIテスト、Releaseビルド（リリースガードを含む）、アーカイブ（署名なしでよい）。
- アーカイブの中の Info.plist、PrivacyInfo.xcprivacy、フレームワークを調べて、点検する。
- PASS / FAIL / NOT RUN を、項目ごとに書く。NOT RUN の理由も書く。

## 7. 私がやることの一覧（出力：OWNER_CHECKLIST.md）
私しかできない作業を、**順番**に、画面の名前・リンク・貼り付ける文字つきで書く。
- Appleの契約、Bundle ID、アプリ、課金商品、AdMob、公開ページ、
  アーカイブとアップロード、ビルドの選択、各入力欄、提出。
- 待ち時間のある作業（契約、審査）を、最初に置く。
- 想定される、つまずきと対処（ITMS-の番号、「ビルドを選択」、サポートURL必須、
  サイズ別のスクリーンショット欄、アプリのプライバシーの「公開」、など）を付ける。

# 完了の報告の形
1. 作ったファイルの一覧（パス）
2. 実行したコマンドと、本物の結果（PASS / FAIL / NOT RUN）
3. 私への質問（私しか知らないことだけ）と、仮置きした値の一覧
4. 「要確認」「報告に基づく」とした項目の一覧
5. 私がやる作業の最初の3つ
6. コミットのSHA（pushは、私が指示するまでしない）

では、手順0から始めてください。
```

## この依頼文の使い方

- **一度に全部を実行させる**必要はありません。手順0〜1だけを実行させて、結果を見てから、続けてもよいです。
- **私の了承が要る操作**（公開、push、アップロード）では、AIが、必ず止まって確認します。止まらないときは、依頼文の「守ること」の3を、もう一度、強調してください。
- 作らせたものは、**そのまま信じず**、App Store Connectの画面と、見比べてください。
- 却下されたら、**メールの全文を貼って**、「原因を調べ、直し、再発防止のチェックを足し、テストで確かめて」と頼みます。

# 付録E 用語集

| 用語 | 説明 |
|---|---|
| Account Holder | Apple Developerアカウントの所有者。契約の承認ができる |
| ADR | Architecture Decision Record。判断とその理由の記録 |
| App Review | Appleの人間の審査 |
| ATT | App Tracking Transparency。トラッキングの許可画面 |
| Bundle ID | アプリの識別子（逆ドメイン形式） |
| dSYM | デバッグ用の記号情報。クラッシュ報告を読みやすくする |
| ITMS-番号 | アップロード後の自動検証が返す、エラーの番号 |
| Paid Applications Schedule | 有料App契約。課金商品を作る前に必要 |
| SKU | 管理用の文字列。ユーザーには見えない |
| TestFlight | 実機での試験配布 |
| UMP | User Messaging Platform。同意の確認（Google） |
| xcconfig | Xcodeの設定をまとめるファイル |
| アーカイブ | 提出用にまとめた、アプリの梱包 |
| 非消耗型 | 一度買えばずっと使える課金の種類 |
| プライバシーマニフェスト | `PrivacyInfo.xcprivacy`。収集とAPIの使用の宣言 |
