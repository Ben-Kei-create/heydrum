# はじめに

## この本について

この本は、**個人開発者が、作ったiPhoneアプリをApp Storeに出すまで**の道のりを、実際にやった順番どおりに書いた手引きです。

ターゲットは次のような人です。

- Xcodeでアプリは作れる（または、AIと一緒に作った）。でも **App Store Connectの画面を前にして、何から手を付けるのか分からない**。
- 「審査用に追加できません」「バイナリが無効」と言われて、**どこを直せばいいのか分からない**。
- 広告（AdMob）や課金（アプリ内課金）を入れたので、**プライバシーの回答や契約が不安**。

この本の中心にあるのは、筆者が実際にアプリ「ヘイドラム」（2つの音を鳴らし、文字を大きく読み上げるiPhoneアプリ）を提出したときの記録です。順調にいった部分だけでなく、**自動検証で2回弾かれ、ビルド番号を3回上げた失敗**も、そのまま載せています。うまくいかなかった話のほうが、あなたの時間を節約するはずだからです。

## この本の約束

1. **順番どおりに読めば、提出ボタンまで進める。** 章は「契約 → 登録 → 設定 → ビルド → 入力 → 提出 → 却下されたら」の順です。
2. **画面の名前、入力する文字、コマンドは、そのまま写せる形で書く。**
3. **分かっていることと、推測を分ける。** Appleの公式の保証がない部分は「報告に基づく」と明記します。
4. **コピーして使える資料を付ける。** 巻末に、チェックリスト、文字数の上限、画像のサイズ、そしてAI（Claude Code）に渡せる**依頼文のひな形**があります。

## 読む前に知っておいてほしいこと

### 情報の時点

画面の名称、画像のサイズ、規約は、AppleやGoogleが予告なく変えます。この本に書いた値は、**2026年10月時点**の筆者の実体験です。迷ったときは、**App Store Connectの画面の表示とエラーメッセージが正**です。この本と画面が食い違ったら、画面を信じてください。

### この本が扱わないもの

- SwiftUIなどの実装の方法（アプリの作り方）。
- 広告収益や売上を伸ばす方法（ASO、マーケティング）。
- 法律や税務の個別の助言。契約、税、プライバシーポリシーの内容は、最終的には**あなた自身の責任**で判断してください。必要なら専門家に相談してください。

### 前提

- Macと、最近のXcodeがある。
- iPhone専用アプリを、日本のApp Storeに出す。
- 広告は Google AdMob、課金は非消耗型のアプリ内課金（買い切り）の例で説明します。使わない人は、その章を飛ばしてください。

### 登場するもの、しないもの

本文中の `com.yourname.appname` や `ca-app-pub-XXXX...` は、**架空の例**です。あなたの値に置き換えてください。筆者の本番のIDや連絡先は載せていません。AppleやGoogleの製品名は、説明のために使っています。各社の商標です。**本書は個人の著作物であり、Apple Inc.、Google LLC、Anthropic, PBC、およびその他の会社とは関係がありません。**

### AI生成についての開示

この本の文章は、AI（Anthropic社のClaude）が、筆者との実際の作業の記録をもとに作成した原稿です。筆者が内容を確認し、編集しています。手順やコマンドは、筆者のアプリの提出作業の中で実際に動かして確かめたものを中心に書いていますが、**画面や規約は変わります**。最新の公式情報も、あわせて確認してください。

### 筆者について

個人でiPhoneアプリ「ヘイドラム」を作り、App Storeに申請した。

## この本の使い方

最短で提出したい人は、次の順に読むと速いです。

1. 第1章（全体像）で、必要なものと順番を把握する。
2. 第2〜4章で、契約とアプリの登録を済ませる。待ち時間があるので、**先に**やる。
3. 第7〜8章で、ビルドを作ってアップロードする。
4. 第9〜11章で、ストアの情報と画像を入れて、提出する。
5. 却下されたら、第12章を開く。

巻末の付録には、印刷して手元に置けるチェックリストと、「AIに投げる依頼文」があります。**付録Dは、実装が終わった段階で、そのままClaude Codeに貼ってください。** 申請に必要な文言、画像、公開ページ、プライバシーの回答案を、まとめて作らせるためのものです。
