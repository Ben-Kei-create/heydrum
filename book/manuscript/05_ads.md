# 第5章 広告（AdMob）：同意、トラッキング、テストID

広告を入れないなら、この章は飛ばしてください。

## 5-1 広告の部品を理解する

広告を入れると、次の3つの仕組みが出てきます。

| 名前 | 誰のもの | 役割 |
|---|---|---|
| AdMob | Google | 広告の配信。広告ユニットのIDを使う。 |
| UMP（ユーザー同意） | Google | 地域の法律（GDPRなど）に基づく同意の確認。 |
| ATT | Apple | 「他社のアプリやサイトを横断して、あなたの行動を追跡することを許可しますか？」の画面。 |

**広告のリクエストを送る前に**、同意の確認が済んでいることが、守るべき順番です。この本の例のアプリは、次の順にしています。

```
アプリ起動
  → 購入済みか確認（検証済みの権利）
  → 購入済みなら、広告の仕組みを一切動かさない
  → 未購入なら、同意（UMP）を確認
  → 広告が出せる状態になったら、ATTの許可画面
  → 広告SDKを起動して、広告をリクエスト
```

**購入済みの人に、広告のリクエストを送らない**こと。**同意が確定する前に、広告のリクエストを送らない**こと。この2つが、広告のコードで一番大事な決まりです。

## 5-2 AdMobでアプリと広告ユニットを作る

1. <https://admob.google.com/home/> にログインする。
2. 「アプリ」→「アプリを追加」→ iOS を選ぶ。
3. アプリがストアに公開されているか聞かれる。まだなら「いいえ」。名前を入れる。
4. 作成されると、**アプリID**が表示される。形式：`ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY`
5. そのアプリの「広告ユニット」→「広告ユニットを追加」→ **バナー**。名前を付けて作成する。**広告ユニットID**が表示される。形式：`ca-app-pub-XXXXXXXXXXXXXXXX/ZZZZZZZZZZ`

アプリIDは「`~`」、広告ユニットIDは「`/`」で区切られています。**間違えて入れ替えると動きません。**

## 5-3 同意メッセージ（UMP）を公開する

AdMobの「**プライバシーとメッセージ**」で、同意メッセージ（欧州の規制、米国の州の規制など）を作り、このアプリに適用して**公開**します。**ここを飛ばすと、地域によって広告が出ません。**

公式の手順：<https://developers.google.com/admob/ios/privacy>

## 5-4 テストIDと本番ID

| | 開発中 | 本番 |
|---|---|---|
| 広告ユニットID | Google公式のテスト用ID | 自分のID |
| 使う場所 | Debugビルド | Releaseビルド |

- 開発中は、**Google公式のテスト用ID**だけを使う。これは、Googleの公式ドキュメントに載っている、誰でも使える共通のIDです。
- **自分の本番の広告を、自分でタップしてはいけません。** 無効なトラフィックとして、アカウントの停止につながります。
- 本番のIDは、**ソースコードにも、gitのリポジトリにも書かない**。第6章の方法で、設定ファイルに分ける。
- 広告ユニットを作った直後は、広告が出ない、または少ないことがあります。AdMob側の準備に、数時間から1日ほどかかることがあります。**空の広告枠は、異常ではありません。**

## 5-5 ATT（トラッキングの許可画面）

広告をユーザーに合わせて出す（パーソナライズ広告）なら、ATTの許可画面が必要です。

### 実装の要点

- `Info.plist` に、`NSUserTrackingUsageDescription`（許可画面に出る説明文）を入れる。
- 説明文は、日本語で、**許可しなくてもアプリの機能が使えることを書く**と親切。例：「広告をお客様に合ったものにするために、広告識別子を使用します。許可しなくてもアプリの機能はすべて使えます。」
- 許可画面を出すのは、**アプリがアクティブな状態のとき**だけ。非アクティブだと、表示されない。
- ATTの許可の結果で、**アプリの機能を制限してはいけない**（広告以外の機能を、許可と引き換えにしない）。

### 実体験

GoogleのUMPが、ATTの前に、「このアプリは無料で提供するために広告を表示します」のような**説明の画面**（IDFAの説明メッセージ）を出すことがあります。そのあとにiOSの許可画面が出ます。**自分で作った説明画面ではありません。** 設定画面で、AdMobの側が出している画面です。

## 5-6 広告枠の置き方

- アプリの下部に、**全画面で同じ位置・同じ高さ**の広告枠を、1つだけ置く（画面ごとに別々に作らない）。
- 広告がまだ読み込めていない、同意が得られていない、オフラインのときは、**空の枠**にする。ダミーの広告を描かない。
- 購入済みなら、**枠ごと消す**。
- キーボードが出ている間だけ、広告枠を隠すのは、妥当な例外。

### バナーの大きさ

AdMobのバナーのSDKは、画面の幅に合わせたサイズ（アンカー型のアダプティブバナー）を使います。SDKのバージョンによって、使うべきAPIの名前が変わります。**筆者の使った版では、従来の標準の関数が非推奨になり、「大きめ」の関数が推奨されていました。** 大きめを選ぶと、広告枠が高くなり、画面が狭くなります。画面のレイアウトに影響するので、SDKの警告が出たら、枠の高さを実機で確認してください。

## ハンズオン：テスト広告を表示して、順番を確かめる

| # | やること | 成功の目安 |
|---|---|---|
| 1 | AdMobでアプリと、バナーの広告ユニットを作り、IDを控える（**本番IDは、コードに書かない**） | IDが2つ（アプリID `~`、ユニットID `/`）ある |
| 2 | 「プライバシーとメッセージ」で同意メッセージを作り、公開する | 状態が「公開済み」 |
| 3 | Debugビルドを、Googleのテスト用IDで動かす | 画面の下に、**「Test Ad」と書かれた広告**が出る |
| 4 | 購入済みの状態にする（テスト用の仕組みで） | 広告枠ごと、消える。広告のリクエストが送られない |
| 5 | 初回起動で、同意 → ATTの順に画面が出るか見る（出る地域のみ） | 同意の画面のあとに、トラッキングの許可画面が出る |
| 6 | ATTで「許可しない」を選ぶ | アプリの機能は、すべて使える |

**確認：** テスト広告が出て、購入済みで消えれば成功です。**自分の本番広告は、押さないでください。**

## 5-7 この章のチェックリスト

```
□ AdMobでアプリと広告ユニットを作り、IDを控えた
□ 同意メッセージ（UMP）を公開した
□ 開発中はGoogleのテストIDだけを使っている
□ 本番IDは、ソースとgitの外にある（第6章）
□ 同意の前、購入権利の確定前に、広告をリクエストしない
□ 購入済みは、広告の仕組み自体を動かさない
□ ATTの説明文を日本語で入れた（NSUserTrackingUsageDescription）
□ 自分の本番広告をタップしない
```
