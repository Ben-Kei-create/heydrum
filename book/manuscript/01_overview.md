# 第1章 全体像：提出までに何があるか

## 1-1 いちばん大事な心構え

App Storeへの提出は、**コードの作業よりも、手続きと入力の作業**です。しかも、手続きには**待ち時間**があります。契約の承認、口座の確認、審査、そして自動検証。待ち時間のあるものを、**先に**始めてください。これが、この本で一番大事な教えです。

もう一つ。提出は一発では通らないことがあります。筆者の場合、**ビルドは3回アップロードし、そのうち2回は、Appleの自動検証のメールで弾かれました。** 弾かれることを前提に、「何が起きたか」を読み取る力が、結局いちばん役に立ちます。

## 1-2 用語の整理

| 用語 | 意味 |
|---|---|
| Apple Developer Program | アプリをApp Storeに出すための、Appleの有料の会員制度（年額）。 |
| App Store Connect | アプリの登録、ビルドの選択、掲載情報、審査の提出を行う、Appleのウェブサイト。 |
| Bundle ID | アプリの識別子（例 `com.yourname.appname`）。逆ドメイン形式。**登録したら変更できない。** |
| ビルド | Xcodeで作り、アップロードしたアプリの本体。バージョン（1.0）と、ビルド番号（1, 2, 3…）で区別する。 |
| アーカイブ | Xcodeが作る、提出用の梱包。ここからアップロードする。 |
| TestFlight | 提出前後に、実機で試すための配布の仕組み。 |
| 審査（App Review） | Appleの人間の審査。通常24〜48時間。 |
| 自動検証 | アップロード直後に、機械が行う形式のチェック。弾かれるとメール（`ITMS-` で始まる番号）が来る。 |
| ITMS-番号 | 自動検証のエラーの番号。**この番号が、原因を調べる最大の手がかり。** |
| 非消耗型 | 一度買えばずっと使える、アプリ内課金の種類。「広告を消す」に向く。 |
| AdMob / UMP / ATT | 広告の仕組み（Google）／同意の確認（Google）／トラッキングの許可（Apple）。 |

## 1-3 全体の流れ（チェックリスト）

```
A. 先にやる（待ち時間があるもの）
  □ Apple Developer Program に加入する
  □ 「有料App契約」を承認する（Account Holderが行う。口座・税務も）

B. 登録
  □ Bundle ID を登録する（変更不可）
  □ App Store Connect で「新規App」を作る
  □ （課金あり）アプリ内課金の商品を作る（製品IDは変更不可）
  □ （広告あり）AdMobでアプリと広告ユニットを作り、同意メッセージを設定する

C. 公開ページ
  □ プライバシーポリシーのURL（https の公開ページ）
  □ サポートのURL（https の公開ページ、連絡先つき）

D. アプリ側
  □ 秘密の設定をgit管理の外に出す
  □ リリースガード（空、テスト用ID、テンプレート値をReleaseで弾く）
  □ 権限、暗号化、プライバシーのマニフェスト、素材のライセンス表記

E. ビルド
  □ アーカイブ → アップロード → 処理を待つ

F. App Store Connectの入力
  □ ビルドの選択、掲載情報、画像、プライバシー、コンテンツ配信権、審査情報

G. 提出 → 審査 → リリース
H. TestFlightで実機確認（提出の前でも後でもよい）
```

## 1-4 かかる時間の目安

| 作業 | 目安 |
|---|---|
| 契約と口座・税務の入力 | 当日〜数日（承認待ちを含む） |
| Bundle ID、アプリ、課金商品の登録 | 1時間ほど |
| AdMobのアプリ・広告ユニット・同意メッセージ | 1時間ほど |
| 公開ページ（サポート、ポリシー）の用意 | 1〜2時間（AIに作らせれば30分） |
| アーカイブとアップロード | 30分〜1時間（処理待ちを除く） |
| ストア情報と画像の入力 | 2〜3時間 |
| 審査 | 24〜48時間 |

初回は、半日〜1日。2回目からは、1〜2時間まで縮みます。この本の付録には、2回目以降を速くするための資料があります。

## 1-5 「AIと一緒に進める」ということ

筆者は、この作業の大半を、AI（Claude Code）と進めました。AIが得意なのは、次のことです。

- 掲載文（説明文、キーワード）や、プライバシーポリシーの下書きを作る。
- スクリーンショットを、UIテストで自動で撮る。
- 設定ファイルの整合性を調べるスクリプトを書く。
- エラーのメールを貼ると、原因の候補を挙げ、直して、テストで確かめる。

逆に、**AIにはできないこと**があります。

- App Store Connectにログインして、操作すること。
- 契約の承認、口座の入力、パスワードの入力（これは、AIがやってはいけないことでもある）。
- 公開してよいかの判断。メールアドレスや名前が公開されるページを、AIが勝手に公開してはいけない。

この本では、**「AIに頼む作業」と「あなたがやる作業」**を、はっきり分けて書きます。分けておくと、迷いません。
